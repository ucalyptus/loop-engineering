  \vspace{0.3cm}

     & \textbf{Goal} & \textbf{Sensor} & \textbf{Comparator} & \textbf{Actuator} \\
    \midrule

\begin{frame}{How control loops fail: Maxwell, \emph{On Governors} (1868)}
  Steam-engine governors \alert{hunted}: they overshot the target speed, corrected, and overshot again. Maxwell explained the cause in 1868, and his paper is one of the first texts of control theory.
  \vspace{0.3cm}

  \footnotesize
  \begin{tabular}{L{3.2cm}L{5cm}L{5.3cm}}
    \toprule
    \textbf{Control term} & \textbf{What it means} & \textbf{In an agent loop} \\
    \midrule
    Negative feedback & push against the error & undo a change that made the result worse \\
    Damping & slow down after an overshoot & make smaller changes, and wait longer after a miss \\
    Oscillation (hunting) & overshoot, correct, repeat & fix one test, break two, and repeat \\
    Steady-state error & stop short of the goal & the agent cannot close the last gap \\
    Saturation limits & the valve has a maximum opening & limits on rounds, time and money \\
    \bottomrule
  \end{tabular}
\end{frame}

\begin{frame}{Ashby's Law: you can only control what you can sense}
  \begin{block}{Law of Requisite Variety (W. Ross Ashby, \emph{An Introduction to Cybernetics}, 1956)}
    Only variety can absorb variety. A regulator can correct only the disturbances that it can identify.
  \end{block}
  \vspace{0.2cm}
  \begin{itemize}
    \item In an agent loop, \textbf{the checks are the sensors}. The loop cannot be better than its checks.
    \item The loop ships any bug that the tests do not detect.
    \item Goodhart's law applies: a measure that becomes a target stops being a good measure.
    \item For an agent, the cheapest way to make a failing test pass is to \alert{edit the test}.
  \end{itemize}
  \vspace{0.2cm}
  \centering\textbf{Add sensors before you add a smarter planner.}
\end{frame}

\section[Kubernetes]{Kubernetes: Cybernetics for Infrastructure}

\begin{frame}{The reconciliation loop}
  \begin{columns}[T]
    \begin{column}{0.5\textwidth}
      \begin{enumerate}
        \item \textbf{Desired state}: a manifest says what should exist
        \item \textbf{Observe}: read the current state
        \item \textbf{Diff}: compare desired vs.\ actual
        \item \textbf{Act}: make the smallest change that closes the gap
        \item \textbf{Repeat}: forever
      \end{enumerate}
    \end{column}
    \begin{column}{0.45\textwidth}
      \begin{block}{Level-triggered, not edge-triggered}
        A controller acts on \emph{the current state}, not on the last event. If it misses an event, the next pass still finds the gap.
      \end{block}
    \end{column}
  \end{columns}
  \vspace{0.3cm}
  The controller does not run a script from start to end. It calculates only the \emph{next correction}. If a pod stops, the loop starts a new pod, so \alert{self-healing comes from the loop}, not from special-case code.
\end{frame}

\begin{frame}{The control plane, mapped}
  \centering
  \includegraphics[width=0.82\linewidth]{pic/controlplane.png}
\end{frame}

\begin{frame}{MLOps already runs on these loops}
  \begin{itemize}
    \item \textbf{GitOps} (Argo CD, Flux): git holds the desired state, and a controller syncs the cluster to it.
    \item \textbf{Continuous training}: if a metric drops below the line, retrain until the metric is above the line again.
    \item \textbf{Progressive delivery}: if canary metrics get worse, the system rolls back.
    \item \textbf{Data validation before training}: a gate rejects bad input, like an admission webhook.
  \end{itemize}
  \vspace{0.4cm}
  \begin{block}{What is new}
    Only the actuator. A language model now makes the change, and it can make \emph{any} change, bad changes too. The other parts stay the same.
  \end{block}
\end{frame}

\section[Agent loops]{Agents: Same Machine, New Actuator}

\begin{frame}{Same loop, new actuator}
  \centering
  \includegraphics[width=0.78\linewidth]{pic/loops.png}
\end{frame}

\begin{frame}{Design rules that transfer directly}
  \footnotesize
  \begin{tabular}{L{2.8cm}L{5.2cm}L{5.6cm}}
    \toprule
    \textbf{Rule} & \textbf{In Kubernetes} & \textbf{In an agent loop} \\
    \midrule
    Declarative & the manifest says \emph{what}, not \emph{how} & ``all checks pass'' is better than a 47-step checklist \\
    Observe first & read the API server before each action & read the code and run the tests before each edit \\
    Small diffs & change one thing per pass & one target per round, with a limit on diff size \\
    Idempotent & a second pass causes no damage & ``the file contains X'', not ``append Y'' \\
    Crash-only & a controller can stop at any time & git stores the progress, and the agent stores nothing \\
    Bounded ownership & labels and selectors & one loop owns one directory \\
    \bottomrule
  \end{tabular}
\end{frame}

\begin{frame}{loopctl in one picture}
  \centering
  \begin{tikzpicture}[node distance=0.45cm]
    \node (obs) [blk, minimum width=1.6cm] {observe\\\tiny run checks};
    \node (dec) [blk, minimum width=1.6cm, right=of obs] {decide\\\tiny pick target};
    \node (act) [blk, minimum width=1.6cm, right=of dec] {act\\\tiny agent edits};

    \draw[flow] (ver.south) -- ++(0,-0.5) -| node[lbl, pos=0.25, below] {repeat until every check passes or a breaker trips} (obs.south);
    \draw[flow, dashed] (ver.north) -- ++(0,0.45) -| node[lbl, pos=0.25, above] {broke a passing check: git revert} (com.north);
    \draw[flow, dashed] (adm.north) -- ++(0,0.45) -| node[lbl, pos=0.25, above] {rejected: discard} (act.north);
  \end{tikzpicture}

  \vspace{0.3cm}
  \small
  \begin{itemize}
    \item loopctl has about 970 lines of Python and uses only the standard library. Git is its etcd: each kept change is a commit.
    \item The agent is a shell command: pi, Claude Code, Codex or a script.
    \item You can stop loopctl at any time. When you start it again, it continues from the last commit with the same budgets.
  \end{itemize}
\end{frame}

\begin{frame}[fragile]{The goal is a file}
\begin{lstlisting}[language=toml]

goal  = "Ship-ready churn model: the data contract holds, holdout AUC is at least 0.85, and the model card documents the model."
actor = 'pi -p "$(cat)"'      # any agent CLI; the prompt arrives on stdin
fresh_clone = true            # observe a clean clone every round: no stale reads

[[checks]]                    # desired state = every check exits 0
name = "quality"               # (plus "schema" and "model-card")
run  = "python3 eval.py --min-auc 0.85"

[[admission]]                 # policy gate: hands off the sensors
name = "sensors-untouched"
run  = "git diff --cached --quiet -- eval.py validate.py check_card.py schema.json data/"

[limits]                      # the safety governor
max_diff_lines   = 80         # damping: big changes are rejected
stall_iterations = 3          # steady-state error: give up
max_regressions  = 2          # oscillation: stop thrashing
\end{lstlisting}
\end{frame}

\section[Failure modes]{When Loops Go Wrong}

\begin{frame}{Kubernetes already learned these lessons}
  \footnotesize
  \begin{tabular}{L{2.6cm}L{4.4cm}L{6.4cm}}
    \toprule
    \textbf{Failure} & \textbf{Looks like} & \textbf{loopctl's answer} \\
    \midrule
    Thrashing & fix one test, break two & verify each commit, revert a regression, stop after \texttt{max\_regressions} \\
    Stale reads & decisions from old data & run the checks again each round, on a fresh clone if you want \\
    Endless loop & the goal is out of reach & limits on rounds and time, and \texttt{stall\_iterations} \\
    Fighting loops & two loops, one directory & a lease file, and a halt if the agent edits outside the directory \\
    Sensor tampering & the agent edits the test & admission checks reject the change \\
    Blind loop & no signal to steer by & the loop cannot fix this: add checks \\
    \bottomrule
  \end{tabular}
\end{frame}

\begin{frame}[fragile]{Live failure: loopctl stops the thrashing}
  A worker that fixes \texttt{add} but breaks \texttt{mul} every time:
\begin{lstlisting}[style=term]
[calc] observe: 1/4 passing, failing ['add', 'sub', 'div']
[calc] act #1: target `add`
[calc] committed 84dcb427 (4 lines)
[calc] observe: 1/4 passing, failing ['sub', 'mul', 'div']
[calc] reverted 84dcb427: broke ['mul']
[calc] act #2: target `add`
[calc] committed 8a047e50 (4 lines)
[calc] observe: 1/4 passing, failing ['sub', 'mul', 'div']
[calc] reverted 8a047e50: broke ['mul']
[calc] thrashing: 2 reverted regressions
\end{lstlisting}
  \small loopctl reverts each regression (negative feedback) and stops after two, so the loop does not hunt. Git keeps every attempt for a human to read.
\end{frame}

\begin{frame}[fragile]{Live failure: the agent edits the check}
  This worker tries to fix \texttt{quality} with a lower AUC bar in \texttt{eval.py}:
\begin{lstlisting}[style=termsm]
[churn] act #2: target `quality`
[churn] rejected: admission[sensors-untouched]: exit 1
[churn] act #3: target `quality`
[churn] rejected: admission[sensors-untouched]: exit 1
[churn] act #4: target `quality`
[churn] rejected: admission[sensors-untouched]: exit 1
[churn] unreachable: no progress in 3 iterations; still failing ['quality', 'model-card']
\end{lstlisting}
  \vspace{0.1cm}
  \begin{itemize}
    \item One line of shell in an admission webhook blocks this Goodhart attack.
    \item A second gate blocks model code that reads the holdout set (\texttt{no-holdout-in-model-code}).
    \item The loop stops and does not ship a false pass.
  \end{itemize}
\end{frame}

\section[Decider]{A Small Brain That Decides}

\begin{frame}{The scheduler picks a node, and the kubelet runs the pod}
  \begin{columns}[T]
    \begin{column}{0.5\textwidth}
      \textbf{Kubernetes scheduler}
      \begin{itemize}
        \item filter: which nodes \emph{can} run this pod?
        \item score: which is best?
        \item pick: one node gets the pod
      \end{itemize}
      \vspace{0.2cm}
      \textbf{Same split for agents}
      \begin{itemize}
        \item a small, fast model \textbf{decides}
        \item a big, slow model \textbf{does}
        \item the checks \textbf{judge}
      \end{itemize}
    \end{column}
    \begin{column}{0.46\textwidth}
      \begin{block}{TypeSafe Jev}
        Jev answers typed questions with probabilities, not free text. loopctl sends one request per round:
        \begin{itemize}
          \item move: act / ask a human / stop
          \item target: which failing check next
        \end{itemize}
      \end{block}
    \end{column}
  \end{columns}
  \vspace{0.2cm}
  \small Guardrails: the decider cannot judge pass or fail, and it cannot pick a passing check. Under 50\% confidence, it asks a human. If it fails, loopctl uses the simple rule.
\end{frame}

\begin{frame}[fragile]{Rules vs.\ Jev: an impossible check listed first}

\section[Outer loop]{The Loop Above the Loop}

\begin{frame}[fragile]{The hill-climbing machine}
  \begin{columns}[T]
    \begin{column}{0.48\textwidth}
      The same loop, one level up:
      \begin{enumerate}
        \item ship a v0 agent
        \item record what it does (traces)
        \item mine traces for failure patterns
        \item turn failures into checks
        \item improve the agent, then repeat
      \end{enumerate}
      \small Here the setpoint is \emph{agent quality}, and you are the actuator.
    \end{column}
    \begin{column}{0.5\textwidth}
\begin{lstlisting}[style=termsm]
$ loopctl report loop.jev.toml
calc-jev: 3 actions, 3 commits, 0 rejected,
  0 reverted, 0.1s acting
last outcome: unreachable (decider chose stop)

checks observed failing:
     4  gpu
     3  div
     2  sub
     1  add

decisions:
     3  decider: act
     1  decider: stop

\begin{frame}{Takeaways}
  \begin{enumerate}
    \item \textbf{Declare the exit condition, not the path.} Checks are your setpoint.
    \item \textbf{Your checks are your sensors.} The loop is only as good as what it can see.
    \item \textbf{Never let the actuator touch the sensor.} Brain outside, hands inside.
    \item \textbf{Observe before every action.} Do not trust the memory of the agent.
    \item \textbf{Make one small change per round, and verify it.} Undo any change that makes the result worse.
    \item \textbf{Keep actions safe to repeat, and keep state outside the agent.} Then you can stop the agent at any time.
    \item \textbf{Install a governor.} Set limits on rounds, time and money, and add a human gate.
    \item \textbf{Let a small model decide and a big model do.} The checks still judge.
  \end{enumerate}
  \vspace{0.2cm}
  \centering\textit{Loop engineering is Kubernetes for agents, and Watt's governor for software.}
\end{frame}
